# Zcode Bridge — 给 Muse 安装的 Zcode 通知桥

把这份技能装到你的工作区。它的用途：**当你在某个回合里产生了想告诉
Zcode（用户的编程 agent）的结果、图片或任务时，按下面的协议把通知发出去**。
Zcode 那一侧有一个 `muse_notifications` 工具在轮询这个会话，凡是按协议发
出的内容都会被它捕获并带回给用户。

## 通知协议（唯一的约定）

当你想通知 Zcode 时，在你的**专用侧聊会话**（session_id 以 `muse-agent-`
开头、由 Zcode 创建的那个；如果当前回合就来自那个会话，直接在本会话回复
即可）里发一条消息，满足以下任一形态即可：

1. **纯文本**：直接把通知写成文字。Zcode 会原样转达。
2. **带图片**：图片生成后，把每张图**转存为 muse.ai/files 公网链接**
   （用你的文件上传能力，或者直接把 `https://muse.ai/files/...` 链接贴在
   回复文字里）。Zcode 会下载并在用户的编程环境里内联显示。
3. **结构化通知**（推荐用于任务类通知）：在回复文字里用这个格式开头，
   之后跟正文：

   ```
   [zcode-notify]
   type: task-done | task-failed | info | image
   task: <一句话任务名>
   ---
   <正文，可以多行>
   ```

   Zcode 解析 `type` 和 `task` 字段展示；没有这个头的消息也会被当作
   `info` 转达，所以这个头是可选的增强。

## 什么时候该发通知

- 用户通过 Zcode 委托你做的任务完成/失败时（画图、搜索、文件处理……）
- 你在自己的回合里发现用户可能关心的紧急信息时
- **不要**把普通聊天对话当作通知重复发送；只发"Zcode 应该知道的事"

## 图片转存规程（每次画图后如果图片要给 Zcode）

1. 确认图片已在你的沙箱（`imagine_media/` 等）
2. 用 `files.upload` 把文件转存为 muse.ai/files 公网链接
   （⚠️ 这一步可能触发外联审批；审批卡出现时提醒用户去 Muse app 批准）
3. 把链接贴在你的通知回复里（纯文字或 presentation 卡片均可，
   Zcode 两种形态都能识别）

## 不需要安装任何依赖

这份技能只是协议约定，不涉及守护进程、hook 或常驻进程——你自己就是
通知的发起者。之前的验收记录表明 `files.upload` 转存链路已可用
（注意上传审批是逐文件的，目前没有永久放行选项）。
